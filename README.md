# surface-atoms

KMC-симулятор поверхностной кинетики (адсорбция, десорбция, диффузия, рекомбинация) по схеме Marinov et al. Поддерживается загрузка кинетической схемы из YAML (вариант A).

---

## Зависимости

- **Go 1.23** или новее ([go.dev](https://go.dev/dl/)).

Остальные зависимости подтягиваются при сборке (`go mod download` / `go build`):

| Пакет | Назначение |
|-------|------------|
| `github.com/Knetic/govaluate` | Формулы: exp, ln, sqrt, pow, min, max, abs, ^, R=8.31 |
| `github.com/knadh/koanf` + yaml/file | Загрузка `config.yaml` |
| `gopkg.in/yaml.v3` | Парсинг YAML (схема и конфиг) |
| `github.com/xuri/excelize/v2` | Вывод результатов в Excel |
| `github.com/go-echarts/go-echarts/v2` | Графики (HTML) |
| `github.com/tealeg/xlsx` | Чтение/запись xlsx |

Установка зависимостей (из корня проекта):

```bash
go mod download
```

## Сборка и запуск

Сборка:

```bash
go build -o surface-atoms .
```

Запуск — два варианта.

**1. Интерактивно** (программа запросит температуру и время симуляции):

```bash
go run .
# или
./surface-atoms
```

**2. Из командной строки** (удобно для скриптов и пакетной обработки):

```bash
go run . <температура_K> <время_симуляции>
# Пример: 300 K, время 1e-6 с
go run . 300 0.000001
# Время можно с подчёркиванием: 1e-6
go run . 300 1e_6
```

В этом режиме логи выше уровня Error отключаются.

Результаты пишутся в каталог `result <дата-время> T<temperature>K/`: Excel-файл и HTML с графиками.

## Конфигурация

Файл **`config.yaml`** в корне проекта (рядом с исполняемым файлом при `./surface-atoms`, или из текущей директории при `go run .`).

### Основные секции

- **`simulating`** — параметры симуляции:
  - `matrixLenX`, `matrixLenY` — размер решётки (число сайтов).
  - `logPercent` — доля симуляции, по которой пишутся точки в Excel (0.1 = 10%).
  - `floatPrecision` — знаков после запятой в Excel.
  - `stopOnQuasiSteady`, `requiredStableChecks`, `checkParameters` — досрочная остановка при квазистационаре.
  - `graphicsToPlot` — какие графики строить (оси X/Y).

- **`consts`** — константы поверхности:
  - `fDensity` — плотность F-сайтов (см⁻²).
  - `sDensity` — плотность S-сайтов (см⁻²).
  - `fi` — не используется в текущей схеме.

- **`elements`** — список элементов (атомов). Для каждого:
  - `name` — символ (N, O, …).
  - `mass` — масса (а.е.м.).
  - `edes`, `edif` — энергии активации десорбции и диффузии (Дж/моль).
  - `vdes`, `vdif` — частотные факторы (с⁻¹).
  - `er`, `erlh` — барьеры рекомбинации E-R и L-H (Дж/моль).
  - `agDensity` — концентрация атомов в газе (см⁻³), для потока на поверхность.

### Схема (вариант A)

- **`schemePath`** — путь к YAML-файлу кинетической схемы.
  - Если задан (например `configs/scheme_marinov.yaml`) — скорости r1–r5 и вероятности рекомбинации берутся из схемы.
  - Если пустой (`schemePath: ""`) — используются встроенные формулы (legacy).

Путь к схеме задаётся относительно текущей рабочей директории при запуске. Пример:

```yaml
schemePath: "configs/scheme_marinov.yaml"
```

Чтобы отключить схему и вернуться к legacy:

```yaml
schemePath: ""
```

## Схема в YAML (вариант A)

Файл схемы (например **`configs/scheme_marinov.yaml`**) описывает:

1. **`rates`** — список скоростей r1–r5. У каждой записи:
   - `id` — имя (r1, r2, …).
   - `expr` — формула (строка). Переменные: `F_density`, `S_density`, `T`, `atomFlux`, `Edes`, `Edif`, `Vdes`, `Vdif`, `Er`, `Erlh`, `R` (8.31), ранее вычисленные `r1`…`r7`. Функции: `exp`, `ln`/`log`, `sqrt`, `abs`, `pow`, `min`, `max`, `log10`, `exp10`, `pi`. Операторы: `+ - * / ^`.

2. **`probabilities`** — вероятности при исходе диффузии (рекомбинация на S или F). Поля `id` и `expr`. Ожидаемые id: `recomb_S`, `recomb_F`.

3. **`events`** — список процессов для BKL (порядок в файле = порядок в каталоге λ):
   - `event_type`: `adsorption_F`, `adsorption_S`, `desorption_F`, `recomb_ER`, `diffusion`.
   - `rate_id`: один из id из `rates`.
   - `lambda_expr` (опционально): формула λ, например `free_F_sites * r1`. Переменные: `free_F_sites`, `free_S_sites`, `atoms_on_F`, `atoms_on_S`, `r1`–`r7`, `F_density`, `S_density`, `atomFlux`, `T`. Если пусто — подставляется выражение по умолчанию для `event_type` (Marinov).

Симулятор читает `events` из схемы и выбирает шаг BKL по ним. Если `events` пустой — подставляется набор Marinov по умолчанию. Без `schemePath` используются те же пять событий и legacy-формулы `Fill()`.

Изменение формул и списка событий в YAML меняет кинетику без пересборки. После правки схемы достаточно перезапустить симуляцию.

## Тесты

Запуск всех тестов:

```bash
go test ./...
```

Только тесты схемы и симулятора:

```bash
go test ./internal/scheme/... ./internal/simulator/... -v
```

Проверяется: загрузка и валидация схемы, вычисление r1–r5 и вероятностей, совпадение `FillFromScheme` с legacy `Fill`, совпадение λ BKL из `events` с прежними формулами.

```
│   ├── simulator/          # KMC: решётка, BKL, процессы
│   ├── random/             # RNG
│   └── graphic_plotter/    # Построение графиков
├── go.mod
└── README.md
```

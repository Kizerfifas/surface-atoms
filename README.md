# surface-atoms

KMC-симулятор поверхностной кинетики (адсорбция, десорбция, диффузия, рекомбинация) по схеме Marinov et al. Поддерживается загрузка кинетической схемы из YAML (вариант A).

Рядом обычно ставят веб-интерфейс **Surface Kinetics Studio** (`surface-kinetics-studio`) — он редактирует файлы этого проекта и запускает симуляцию кнопками.

## Инструкция «с нуля»: как пользоваться всем стеком

### Что за что отвечает

| Программа | Где лежит | Зачем |
|-----------|-----------|--------|
| **surface-atoms** | этот репозиторий | Считает KMC на решётке, пишет Excel и HTML в папку `result …` |
| **Surface Kinetics Studio** | `surface-kinetics-studio` | Браузерный редактор `config.yaml` и схем, кнопки «собрать / запустить / результаты» |

Studio **не заменяет** симулятор: он меняет файлы на диске и вызывает `go run` в каталоге surface-atoms.

### Типичный сценарий (5 шагов)

1. **Запустить Studio** (см. [развёртывание](#развёртывание-на-другой-машине)): `npm run dev` в `surface-kinetics-studio`, открыть в браузере `http://localhost:5173` (или `:8085` через nginx).
2. **Конфигурация** — задать элементы (N / N+O), плотности F/S, при желании взять параметры из **базы** (Marinov). Сохранить → в файл `surface-atoms/config.yaml`.
3. **Схема** — открыть или создать `configs/scheme_….yaml`, отредактировать скорости и события BKL. Сохранить. Нажать **«Подключить в config.yaml»**, если схема новая.
4. **Запуск** — `go build` (один раз), при желании `go test`, затем **«Запустить симуляцию»** (T и время). Или **пакетный sweep** по T и `agDensity`.
5. **Результаты** — открыть последний прогон, графики и Excel.

### Где лежат файлы на диске

```
surface-atoms/
├── config.yaml              ← конфиг симуляции (элементы, матрица, schemePath)
├── configs/
│   └── scheme_marinov.yaml  ← кинетическая схема (rates, probabilities, events)
└── result 2026-… T300K/    ← результаты прогона (создаёт симулятор)
```

Studio пишет **только** в `config.yaml` и `configs/*.yaml` (плюс журналы sweep в `surface-kinetics-studio/data/sweeps/`).

## Развёртывание на другой машине

### 1. Что установить

| Компонент | Версия | Зачем |
|-----------|--------|--------|
| **Go** | 1.23+ | Сборка и запуск surface-atoms |
| **Node.js** | 18+ | Studio (API + React) |
| **git** | любая | Клонировать репозитории |

Опционально: **nginx** — доступ с другого ПК (Windows / Hyper-V) по IP виртуалки.

### 2. Склонировать проекты

Оба репозитория удобно положить **рядом** в одну папку:

```bash
mkdir -p ~/projects && cd ~/projects
git clone git@github.com:Kizerfifas/surface-atoms.git
git clone git@github.com:Kizerfifas/surface-kinetics-studio.git
```

Если каталоги в другом месте — задайте путь к симулятору переменной (см. ниже).

### 3. Собрать surface-atoms

```bash
cd ~/projects/surface-atoms
go mod download
go build -o surface-atoms .
go test ./internal/scheme/... ./internal/simulator/...
```

Проверка без Studio:

```bash
go run . 300 1e-6
ls -d "result "* | tail -1
```

### 4. Установить и запустить Studio

```bash
cd ~/projects/surface-kinetics-studio
npm install
cd client && npm install && cd ..

export SURFACE_ATOMS_PATH=~/projects/surface-atoms   # обязательно, если не соседняя папка
npm run dev
```

Откройте в браузере: **http://localhost:5173**

Важно: команда **`npm run dev`** поднимает **два** процесса — API на порту **3847** и Vite на **5173**. Если запустить только `npm run dev --prefix client`, в консоли будут ошибки `proxy ECONNREFUSED 127.0.0.1:3847` — это нормально означает, что **бэкенд не запущен**. Исправление:

```bash
npm run dev:server    # только API
# или
npm run dev           # API + фронт
```

### 5. Доступ с Windows (Hyper-V) через nginx (опционально)

На Linux-ВМ (пример из нашей настройки):

```bash
sudo /path/to/nginx/enable-surface-kinetics.sh
cd ~/projects/surface-kinetics-studio && npm run dev
```

С Windows: `http://<IP-виртуалки>:8085` (nginx проксирует на Vite `:5173`).

### 6. Production (без hot-reload)

```bash
cd surface-kinetics-studio/client && npm run build && cd ..
export SURFACE_ATOMS_PATH=~/projects/surface-atoms
NODE_ENV=production npm start
```

Один порт **3847** — и API, и собранный фронт.

### 7. Переменные окружения (шпаргалка)

| Переменная | Где | Значение |
|------------|-----|----------|
| `SURFACE_ATOMS_PATH` | Studio | Абсолютный путь к каталогу **surface-atoms** |
| `PORT` | Studio API | Порт бэкенда (по умолчанию 3847) |

Пример в `~/.bashrc`:

```bash
export SURFACE_ATOMS_PATH="$HOME/projects/surface-atoms"
```

## Обзор Surface Kinetics Studio: страницы и кнопки

### Боковое меню

| Пункт | Назначение |
|-------|------------|
| **Схема** | Редактор `configs/*.yaml` (скорости r1–r5, вероятности, события BKL) |
| **Конфигурация** | Редактор `config.yaml` (элементы, матрица, квази-стационар) |
| **Запуск** | Сборка Go, тесты, одиночный прогон или sweep |
| **Результаты** | Список папок `result …`, графики, Excel |

Переключатель темы — внизу сайдбара.

---

### Страница «Схема»

| Элемент | Действие |
|---------|----------|
| **Выпадающий список «Файл схемы»** | Выбор `configs/имя.yaml` на диске |
| **+ Новая схема** | Создать новый файл (шаблон / копия Marinov / копия текущего) |
| **Сохранить** | Записать на диск **активную вкладку** (форма или YAML уже согласованы, см. ниже) |
| **Подключить в config.yaml** | Прописать `schemePath: "configs/…"` в `config.yaml` (симулятор начнёт использовать эту схему) |
| Вкладка **Форма** | Таблицы rates, probabilities, events; пресеты формул (`arrhenius`, `per`, …) |
| Вкладка **YAML** | Прямое редактирование текста файла; при **переключении вкладок** форма и YAML **синхронизируются автоматически** |
| **+ Скорость / + Вероятность / + Событие** | Добавить строку в форме |

Панели в полях формул: **Пресеты**, **Вручную** (полные формулы), **Функции** (`exp`, `sqrt`, …), **Переменные**, автодополнение **Ctrl+Space**.

---

### Страница «Конфигурация»

| Элемент | Действие |
|---------|----------|
| Пресеты **1 компонент (N)** / **2 компонента (N + O)** | Подставить готовый `config.yaml` |
| **База параметров** | Взять из YAML-базы Marinov (consts, элемент N/O, полный пресет) → запись в `config.yaml` |
| Вкладка **Форма** | `schemePath`, consts, элементы, квази-стационар |
| Вкладка **YAML** | Прямое редактирование `config.yaml`; при смене вкладки — **автосинхронизация** с формой |
| **Сохранить** | Записать `config.yaml` с **текущей активной вкладки** |

Поля элемента: `edes`, `er`, `agDensity` (концентрация в газе → из неё считается поток атомов Φ), `sort` (порядок прогона при нескольких элементах).

### Страница «Запуск»

| Кнопка | Действие |
|--------|----------|

| Блок **Лог** | Вывод команд Go |

Сводка вверху: сколько элементов, какая схема, квази-стационар вкл/выкл.

### Страница «Результаты»

## Форма и YAML — синхронизация

При **переключении вкладки** «Форма» ↔ «YAML» Studio автоматически переносит изменения:

- **Форма → YAML** — сериализация в текст (с проверкой пресетов и формул).
- **YAML → Форма** — разбор YAML; при ошибке синтаксиса вкладка **не переключается**, показывается сообщение об ошибке.

Кнопка **«Сохранить»** одна: пишет на диск содержимое **той вкладки, на которой вы сейчас** (перед записью она ещё раз согласуется с вторым представлением).

Симулятор **всегда читает только файлы на диске**. Пока не нажали «Сохранить» — `go run` видит старую версию.

При **смене файла** в списке или **перезагрузке страницы** форма и YAML снова загружаются с диска и совпадают.

## Сборка и запуск

Сборка:

```bash
go build -o surface-atoms .
```

Запуск — два варианта.

**1. Интерактивно** (программа запросит температуру и время симуляции):

```bash
go run .
# или
./surface-atoms
```

**2. Из командной строки** (удобно для скриптов и пакетной обработки):

```bash
go run . <температура_K> <время_симуляции>
# Пример: 300 K, время 1e-6 с
go run . 300 0.000001
# Время можно с подчёркиванием: 1e-6
go run . 300 1e_6
```

В этом режиме логи выше уровня Error отключаются.

Результаты пишутся в каталог `result <дата-время> T<temperature>K/`: Excel-файл и HTML с графиками.

## Конфигурация

Файл **`config.yaml`** в корне проекта (рядом с исполняемым файлом при `./surface-atoms`, или из текущей директории при `go run .`).

### Основные секции

- **`simulating`** — параметры симуляции:
  - `matrixLenX`, `matrixLenY` — размер решётки (число сайтов).
  - `logPercent` — доля симуляции, по которой пишутся точки в Excel (0.1 = 10%).
  - `floatPrecision` — знаков после запятой в Excel.
  - `stopOnQuasiSteady`, `requiredStableChecks`, `checkParameters` — досрочная остановка при квазистационаре.
  - `graphicsToPlot` — какие графики строить (оси X/Y).

- **`consts`** — константы поверхности:
  - `fDensity` — плотность F-сайтов (см⁻²).
  - `sDensity` — плотность S-сайтов (см⁻²).
  - `fi` — не используется в текущей схеме.

- **`elements`** — список элементов (атомов). Для каждого:
  - `name` — символ (N, O, …).
  - `mass` — масса (а.е.м.).
  - `edes`, `edif` — энергии активации десорбции и диффузии (Дж/моль).
  - `vdes`, `vdif` — частотные факторы (с⁻¹).
  - `er`, `erlh` — барьеры рекомбинации E-R и L-H (Дж/моль).
  - `agDensity` — концентрация атомов в газе (см⁻³), для потока на поверхность.

### Схема (вариант A)

- **`schemePath`** — путь к YAML-файлу кинетической схемы.
  - Если задан (например `configs/scheme_marinov.yaml`) — скорости r1–r5 и вероятности рекомбинации берутся из схемы.
  - Если пустой (`schemePath: ""`) — используются встроенные формулы (legacy).

Путь к схеме задаётся относительно текущей рабочей директории при запуске. Пример:

```yaml
schemePath: "configs/scheme_marinov.yaml"
```

Чтобы отключить схему и вернуться к legacy:

```yaml
schemePath: ""
```

## Схема в YAML (вариант A)

Файл схемы (например **`configs/scheme_marinov.yaml`**) описывает:

1. **`rates`** — список скоростей r1–r5. У каждой записи:
   - `id` — имя (r1, r2, …).
   - `expr` — формула (строка) или **именованный пресет**: `arrhenius(Vdes, Edes)`, `per(Er)`, `adsorption_flux()`, `bkl_sites_rate(free_F_sites, r1)` и т.д. (раскрываются перед вычислением). Можно писать и **вручную**: `Vdes * exp(-Edes / (R * T))`. Переменные: `F_density`, `S_density`, `T`, `atomFlux`, `Edes`, … `R` (8.31), `r1`…`r7`. Математика: `exp`, `ln`, `sqrt`, `pow`, `^`.
   - `functions:` (опционально) — свои пресеты `{ имя: { params: [...], expr: "..." } }`.

2. **`probabilities`** — вероятности при исходе диффузии (рекомбинация на S или F). Поля `id` и `expr`. Ожидаемые id: `recomb_S`, `recomb_F`.

3. **`events`** — список процессов для BKL (порядок в файле = порядок в каталоге λ):
   - `event_type`: `adsorption_F`, `adsorption_S`, `desorption_F`, `recomb_ER`, `diffusion`.
   - `rate_id`: один из id из `rates`.
   - `lambda_expr` (опционально): формула λ, например `free_F_sites * r1`. Переменные: `free_F_sites`, `free_S_sites`, `atoms_on_F`, `atoms_on_S`, `r1`–`r7`, `F_density`, `S_density`, `atomFlux`, `T`. Если пусто — подставляется выражение по умолчанию для `event_type` (Marinov).

Симулятор читает `events` из схемы и выбирает шаг BKL по ним. Если `events` пустой — подставляется набор Marinov по умолчанию. Без `schemePath` используются те же пять событий и legacy-формулы `Fill()`.

Изменение формул и списка событий в YAML меняет кинетику без пересборки. После правки схемы достаточно перезапустить симуляцию.

## Тесты

Запуск всех тестов:

```bash
go test ./...
```

Только тесты схемы и симулятора:

```bash
go test ./internal/scheme/... ./internal/simulator/... -v
```

Проверяется: загрузка и валидация схемы, вычисление r1–r5 и вероятностей, совпадение `FillFromScheme` с legacy `Fill`, совпадение λ BKL из `events` с прежними формулами.

